## 1. 바이너리 준비, 설치 및 기본 구동 (Installation & Verification)

> **안내**: Goslide는 CGO 및 외부 런타임 의존성이 전혀 없는 **단일 정적 바이너리(Single Binary)**이므로, 일반 사용자는 Go 언어 컴파일러나 런타임을 설치할 필요가 없습니다.

- [x] **1.1 [바이너리 실행 권한 및 무의존성 검증]**  
  * **액션**: 배포된 바이너리(또는 `bin/goslide`)에 대해 `chmod +x goslide` 후 `file goslide` 실행  
  * **기대 결과**: `statically linked` 정적 바이너리로 확인되어야 하며, 시스템에 Go 컴파일러가 없어도 단독 실행 가능해야 함
- [x] **1.2 [동적 라이브러리 의존성(CGO) 부재 확인]**  
  * **액션**: `ldd goslide` 실행 (또는 `bin/goslide`)  
  * **기대 결과**: `not a dynamic executable`이 출력되어 glibc나 서드파티 C 라이브러리 의존성이 없어야 함
- [x] **1.3 [사용자 PATH 경로 설치]**  
  * **액션**: `cp goslide ~/.local/bin/` (또는 개발 환경에서 `make install`) 실행 후 터미널 어디서나 `goslide` 명령어 호출 가능 여부 확인  
  * **기대 결과**: `which goslide` 실행 시 정상 경로가 출력되어야 함
- [x] **1.4 [CLI 기본 도움말 실행]**  
  * **액션**: 임의의 디렉토리에서 `goslide --help` 또는 `goslide -h` 실행  
  * **기대 결과**: Goslide 소개, `build`, `init`, `serve` 서브커맨드 및 전역 플래그 목록이 깔끔하게 출력되어야 함
- [x] **1.5 [CLI 다국어 한글 안내 확인]**  
  * **액션**: `goslide --lang=ko --help` 실행  
  * **기대 결과**: CLI 사용법과 설명 문구가 자연스러운 한국어로 출력되어야 함

## 2. 프로젝트 및 슬라이드 생성 (`goslide init`)

- [x] **2.1 [기본 스타터 슬라이드 생성]**  
  * **액션**: 임의의 빈 테스트 디렉토리(`/tmp/goslide-test`)를 만들고 이동 후 `goslide init talk.md` 실행  
  * **기대 결과**: `✓ Starter presentation created at talk.md` 안내와 함께 `talk.md` 파일이 생성되어야 함
- [x] **2.2 [스타터 파일 마크다운 무결성 열람]**  
  * **액션**: 텍스트 에디터나 `head -n 20 talk.md`로 파일 내용 확인  
  * **기대 결과**: 상단 Frontmatter(`title:`, `theme: default`)와 슬라이드 분할선(`---`)이 올바른 GFM 문법으로 채워져 있어야 함
- [x] **2.3 [테마 지정 스타터 생성]**  
  * **액션**: `goslide init clean-talk.md --theme=clean` 실행  
  * **기대 결과**: 생성된 `clean-talk.md`의 Frontmatter에 `theme: clean`이 정확히 설정되어 있어야 함
- [x] **2.4 [기존 파일 덮어쓰기 방어 검증]**  
  * **액션**: 이미 존재하는 파일에 대해 `goslide init talk.md` 재실행  
  * **기대 결과**: 덮어쓰지 않고 에러 메시지(`file ... already exists`)를 출력하며 종료되어야 함
- [x] **2.5 [강제 덮어쓰기 플래그 검증]**  
  * **액션**: `goslide init talk.md --force` 실행  
  * **기대 결과**: 에러 없이 파일이 정상적으로 덮어써져야 함

## 3. 실시간 개발 서버 및 핫리로드 (`goslide serve`)

- [x] **3.1 [개발 서버 호스팅 실행]**  
  * **액션**: 터미널에서 `goslide serve talk.md --port=8080` 실행  
  * **기대 결과**: `Server started at http://localhost:8080` 메시지와 단축키 안내가 출력되며 프로세스가 대기 상태로 유지되어야 함
- [x] **3.2 [웹 브라우저 접속]**  
  * **액션**: 웹 브라우저(Chrome/Firefox)를 열고 `http://localhost:8080` 접속  
  * **기대 결과**: 첫 번째 슬라이드(표지 슬라이드)가 16:9 와이드 비율로 선명하게 로딩되어야 함
- [x] **3.3 [실시간 SSE 핫리로드 (텍스트 수정)]**  
  * **액션**: 브라우저 창을 띄워둔 채로, 다른 터미널/에디터에서 `talk.md`의 첫 슬라이드 제목을 수정하고 저장(`Ctrl+S`)  
  * **기대 결과**: 브라우저에서 **F5(새로고침)를 누르지 않아도 300ms 이내에 수정된 제목이 화면에 자동 갱신**되어야 함
- [x] **3.4 [슬라이드 위치 보존 (Scroll/Index Persistence)]**  
  * **액션**: 브라우저에서 키보드 `→` 키를 2번 눌러 **3번째 슬라이드**로 이동한 상태에서, 에디터로 3번째 슬라이드 본문을 수정하고 저장  
  * **기대 결과**: 핫리로드 갱신 후 첫 페이지로 튕기지 않고 **여전히 3번째 슬라이드 화면에 머물러 있어야 함**
- [ ] **3.5 [문법 오류 시 서버 회복력(Resilience)]**  
  * **액션**: `talk.md`의 Frontmatter를 깨뜨려 저장 (예: `title: [invalid yaml`)  
  * **기대 결과**: 터미널에 에러 로그가 출력되지만 **서버가 다운(크래시)되지 않고**, 브라우저에는 직전 유효 슬라이드가 안정적으로 유지되어야 함

## 4. 슬라이드 뷰 화면 기본 내비게이션 (Navigation & Viewport)

- [x] **4.1 [스페이스바 및 오른쪽 화살표 다음 이동]**  
  * **액션**: 브라우저에서 `Space` 키 또는 `→` (오른쪽 화살표) 입력  
  * **기대 결과**:  다음 슬라이드로 넘어감.(전환 효과는 없음) 
- [x] **4.2 [왼쪽 화살표 이전 이동]**  
  * **액션**: `←` (왼쪽 화살표) 또는 `Backspace` 입력  
  * **기대 결과**: 이전 슬라이드로 정상 복귀해야 함
- [x] **4.3 [Home / End 키 점프]**  
  * **액션**: `End` 키 입력 후 화면 확인, 이어서 `Home` 키 입력  
  * **기대 결과**: `End` 누르면 마지막 슬라이드로 즉시 점프하고, `Home` 누르면 첫 슬라이드로 즉시 돌아와야 함
- [x] **4.4 [숫자 번호 직접 점프 (Jump Buffer)]**  
  * **액션**: 키보드로 숫자 `3` 누르고 1초 내에 `Enter` 키 입력  
  * **기대 결과**: 3번째 슬라이드로 즉시 이동해야 함
- [x] **4.5 [전체화면 모드 토글 (`F` 키)]**  
  * **액션**: `F` 키 입력하여 브라우저 전체화면 진입 후, 다시 `F` 또는 `Esc` 입력  
  * **기대 결과**: 브라우저 UI가 사라지며 16:9 슬라이드가 화면 중앙에 최대 크기로 차오르고, `Esc` 누르면 원상복구되어야 함
- [x] **4.6 [반응형 뷰포트 레터박스]**  
  * **액션**: 브라우저 창 크기를 마우스로 가로/세로로 극단적으로 조절  
  * **기대 결과**: 슬라이드 내부 비율(16:9)이 찌그러지지 않고 상하 또는 좌우에 검은 레터박스가 생기며 중앙 정렬을 유지해야 함

## 5. 실전 프레젠테이션 인터랙션 도구 (Interactive Presentation Toolkit)

발표자가 무대 위에서 청중의 시선을 사로잡기 위해 사용하는 마우스/키보드 인터랙션 도구를 전수 검증합니다.

### 5.1 드로잉 판서 캔버스 (Drawing Canvas & Whiteboard)
- [x] **5.1.1 [단축키 `D`로 드로잉 모드 전환]**  
  * **액션**: 키보드 `D` 키 입력  
  * **기대 결과**: 화면 마우스 커서가 펜(크로스헤어)으로 바뀌고, 하단 툴바의 `펜` 버튼이 활성화(Sky 색상)되어야 함
- [x] **5.1.2 [마우스 드래그 자유 필기]**  
  * **액션**: 슬라이드 본문 위에 마우스 왼쪽 버튼을 누른 채 원형이나 밑줄 그리기  
  * **기대 결과**: 마우스 궤적을 따라 부드럽게 선이 그려져야 함
- [x] **5.1.3 [팔레트 색상 변경 (단축키 `1`~`4` 및 버튼 클릭)]**  
  * **액션**: 드로잉 상태에서 키보드 `2` 누르거나 툴바의 파란색 동그라미 클릭 후 필기, 이어서 `4` 누르거나 노란색 동그라미 클릭 후 필기  
  * **기대 결과**: 지정한 색상(1:빨강, 2:파랑, 3:초록, 4:노랑)으로 선 색상이 즉시 변경되어 그려져야 함
- [x] **5.1.4 [펜 굵기 변경 (단축키 `+`/`-` 및 버튼 클릭)]**  
  * **액션**: `+` 키를 누르거나 툴바의 `굵게` 버튼 클릭 후 필기, `-` 키 누르거나 `얇게` 버튼 클릭 후 필기  
  * **기대 결과**: 굵게(8px)와 얇게(2px) 두께 차이가 명확하게 선에 반영되어야 함
- [x] **5.1.5 [판서 내용 페이지별 유지 검증]**  
  * **액션**: 현재 슬라이드에 낙서를 남긴 상태에서 `→` 키로 다음 슬라이드로 이동했다가, 다시 `←` 키로 복귀  
  * **기대 결과**: 이전 슬라이드의 필기 내용이 사라지지 않고 그대로 보존되어 있어야 함
- [x] **5.1.6 [현재 슬라이드 판서 지우기 (`C` 키)]**  
  * **액션**: 키보드 `C` 키 입력 또는 툴바의 `🗑️ 지우기` 버튼 클릭  
  * **기대 결과**: 현재 슬라이드 위에 그려진 모든 드로잉이 즉시 깨끗하게 지워져야 함
- [x] **5.1.7 [드로잉 모드 해제]**  
  * **액션**: 다시 `D` 키 입력 또는 `Esc` 키 입력  
  * **기대 결과**: 드로잉 모드가 종료되고 일반 슬라이드 내비게이션 모드로 복귀해야 함

- [ ] **6.6 [팝업창 도구로 메인 슬라이드 제어]**

## 7. 마크다운 확장 DSL 시각 렌더링 검증 (Visual Elements)

공식 예제인 `examples/example-dsl.md`를 열거나 `goslide serve examples/example-dsl.md`로 호스팅하여 검증합니다.

- [ ] **7.1 [2단 레이아웃 분할 (`two-cols` & `<!-- split -->`)]**  
  * **액션**: 2단 레이아웃이 적용된 슬라이드로 이동  
  * **기대 결과**: `<!-- split -->`을 기준으로 좌우 50:50 대칭 컬럼으로 내용이 겹침 없이 나란히 배치되어야 함
- [ ] **7.2 [Chroma 다국어 코드 구문 강조]**  
  * **액션**: Go, Python, SQL 등 코드 블록이 있는 슬라이드 확인  
  * **기대 결과**: 키워드, 문자열, 함수명이 올바른 색상으로 구문 강조(Syntax Highlight)되어야 함
- [ ] **7.3 [코드 라인별 하이라이트 & 딤(Dim) 처리]**  
  * **액션**: ` ```go {2,4-5} ` 문법이 적용된 코드 블록 슬라이드 확인  
  * **기대 결과**: 지정된 2번, 4~5번 줄만 밝게 강조되고 나머지 줄은 반투명(Dim) 처리되어야 함
- [ ] **7.4 [스텝 애니메이션 (Fragments)]**  
  * **액션**: 리스트 항목(`* item`)이 있는 슬라이드에서 `Space` 키를 하나씩 입력  
  * **기대 결과**: 슬라이드가 바로 넘어가지 않고, `Space`를 누를 때마다 리스트 항목이 한 줄씩 순차적으로 나타나야 함
- [ ] **7.5 [GFM 알림 박스 (Alert Callouts)]**  
  * **액션**: `> [!NOTE]`, `> [!TIP]`, `> [!WARNING]` 등이 포함된 슬라이드 확인  
  * **기대 결과**: 단순 인용문이 아니라 각 타입별 아이콘(ℹ️, 💡, ⚠️ 등)과 고유 테두리 색상이 적용된 카드 박스로 렌더링되어야 함
- [ ] **7.6 [미디어 및 이미지 크기 제어]**  
  * **액션**: `![w:400 h:200](image.png)` 이미지 슬라이드 확인  
  * **기대 결과**: 지정한 400x200 픽셀 크기에 맞추어 이미지가 왜곡 없이 올바르게 출력되어야 함
