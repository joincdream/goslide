## 1. 의미론적 정보 및 포맷 제약 (Semantic Rules)

* **16:9 뷰포트 고정 높이 원칙**: 슬라이드는 스크롤되지 않는 고정된 화면(1920×1080)입니다.
  * 슬라이드 1장의 총 줄 수는 빈 줄 포함 **최대 10~12줄**을 넘지 않아야 합니다.
  * 2문장 이상의 서술형 줄글은 엄격히 금지하며, 키워드 중심의 **단문 불릿(`- **키워드**: 설명`)**으로 작성합니다.
  * 슬라이드 1장당 불릿 포인트는 **최대 4개** 이내로 제한합니다.
* **청중 본문과 발표 대본의 격리 원칙**:
  * 슬라이드 화면에는 핵심 키워드와 시각적 요약만 노출합니다.
  * 배경 설명, 구체적 수치, 발표 대본은 슬라이드 하단의 **`<!-- note: ... -->` 태그 안으로 전면 격리**합니다.
* **슬라이드 경계 분할 원칙**:
  * 각 슬라이드는 반드시 **단독 행의 `---`**로 분리합니다.
  * 코드 블록(```` ``` ````) 내부에는 절대 `---`를 포함해서는 안 됩니다.
* **2단 레이아웃 필수 분할 원칙 (`<!-- split -->`)**:
  * `<!-- _layout: two-cols -->`를 사용할 때는 반드시 좌측 컬럼과 우측 컬럼 내용 사이에 **단독 행의 `<!-- split -->` 구분자**를 삽입해야 합니다.
  * 좌측: 3~4개의 핵심 불릿 포인트, 우측: 보조 코드 블록, 다이어그램 또는 이미지 배치를 권장합니다.
* **지시어 스코프 원칙 (`_`)**:
  * 지시어 키 앞에 언더스코어(`_`)가 붙으면 **해당 1개 슬라이드에만 일회성 적용**됩니다 (예: `_layout`, `_backgroundImage`, `_paginate`, `_fragmentStyle`).
  * 언더스코어가 없으면 이후 모든 슬라이드로 상속됩니다.

## 2. 지시어 카탈로그 (Directive Catalog)

### 2.1 문서 최상단 전역 설정 (YAML Frontmatter)
```yaml
---
title: "발표 제목"
author: "발표자/조직명"
theme: "clean"      # clean (미니멀 화이트), default (기술 표준), dark (다크 모드)
size: "16:9"        # 16:9 또는 4:3
paginate: true      # 페이지 번호 표기 여부 (true/false)
header: "헤더 문구"  # 전체 상단 공통 헤더
footer: "푸터 문구"  # 전체 하단 공통 푸터
---
```

### 2.2 슬라이드 시맨틱 레이아웃 5종 (`_layout`)
| 레이아웃 | 지시어 | 설명 및 필수 구성 요소 |
| :--- | :--- | :--- |
| **표지** | `<!-- _layout: cover -->` | 발표 타이틀. 대형 H1 제목 + H3 부제목 + 발표자 정보 |
| **간지 (섹션)** | `<!-- _layout: section -->` | 중간 챕터 전환. H1 단독 또는 1줄 요약 인용구 |
| **2단 분할** | `<!-- _layout: two-cols -->` | 2단 병렬 비교. **반드시 좌/우 내용 사이에 `<!-- split -->` 구분자 필수** |
| **풀스크린** | `<!-- _layout: blank -->` | 상하좌우 여백(Padding) 제로. 대형 다이어그램/이미지/수식 |
| **일반 본문** | `<!-- _layout: default -->` | 기본 본문 (생략 시 기본 적용). H2 헤더 + 3~4개 불릿/표/코드 |

### 2.3 시각 스타일 지시어
* **배경 이미지**: `<!-- _backgroundImage: url('images/bg.png') -->`
* **배경 딤(어둡게) 처리**: `<!-- _backgroundDim: 0.5 -->` (0.1 ~ 0.9, 복잡한 사진 위 텍스트 가독성 확보)
* **슬라이드 배경색**: `<!-- _backgroundColor: #0f172a -->`
* **슬라이드 글자색**: `<!-- _color: #ffffff -->`
* **색상 반전 클래스**: `<!-- _class: invert -->`
* **로컬 헤더/푸터/번호 숨기기**: `<!-- _header: "" -->`, `<!-- _footer: "" -->`, `<!-- _paginate: false -->`

### 2.4 발표자 전용 메모 (Speaker Notes)
슬라이드 하단에 작성하며, 발표자 뷰(`P` 키) 및 PPTX 메모에만 표시됩니다:
```markdown
<!-- note:
- 이 슬라이드에서는 2번 불릿의 확장성 이점을 1분 내외로 강조할 것.
- 세션 종료 후 질의응답 시간을 상기시킬 것.
-->
```

### 2.5 지원 마크다운 컴포넌트 & 확장 인터랙션

#### 2.5.1 단계적 빌드 (스텝 애니메이션 / Fragments)
불릿 항목이나 단락 사이에 `<!-- pause -->`를 삽입합니다. `<!-- pause -->` 뒤에 오는 항목은 발표자가 스페이스바 또는 화살표 키를 누를 때마다 순차적으로 하나씩 화면에 나타납니다:
```markdown
- 첫 번째 노출 항목
<!-- pause -->
- 두 번째 노출 항목 (다음 키 입력 시 노출)
<!-- pause -->
- 세 번째 노출 항목 (그 다음 키 입력 시 노출)
```
* **단계적 딤 스타일**: 슬라이드 상단에 `<!-- _fragmentStyle: dim -->`을 추가하면, 미노출 항목이 완전히 숨겨지는 대신 25% 반투명(Dim)으로 먼저 보여 청중의 시선을 자연스럽게 유도합니다.

#### 2.5.2 코드 블록 및 라인별 포커스 강조
Chroma 구문 강조와 함께 특정 라인만 선명하게 강조하고 나머지 라인은 자동으로 흐림(Dim) 처리합니다:
````markdown
```go {2,4-6}
func main() {
    ctx := context.Background() // 2행: 선명하게 강조
    client := NewClient()       // 3행: 흐림(Dim) 처리
    for token := range stream { // 4~6행: 선명하게 강조
        fmt.Println(token)
    }
}
```
````

#### 2.5.3 이미지 크기 조절 및 가운데 정렬
마크다운 이미지 alt 태그 안에 크기(`w:`, `h:`) 및 정렬 지시어를 직접 지정합니다:
```markdown
![w:400 h:250](images/diagram.png)       <!-- 너비 400px, 높이 250px -->
![w:60% center](images/architecture.png)  <!-- 뷰포트 너비 60%, 화면 중앙 정렬 -->
![height:300px](images/screenshot.png)   <!-- 높이 300px, 비율 유지 -->
```

#### 2.5.4 반응형 YouTube 비디오 임베드
마크다운 이미지 문법 안에 유튜브 동영상 링크를 넣으면 16:9 반응형 iframe 플레이어로 자동 변환됩니다:
```markdown
![](https://www.youtube.com/watch?v=dQw4w9WgXcQ)
![](https://youtu.be/dQw4w9WgXcQ?t=1m30s) <!-- 재생 시작 시간 파라미터 지원 -->
```

#### 2.5.5 GFM 알림 박스 (Callout / Alerts)
시각적으로 돋보이는 5종의 알림 박스를 고유 아이콘과 함께 렌더링합니다:
```markdown
> [!NOTE] 참고 사항
> 유용한 배경 지식 및 보충 참고 자료를 안내합니다.

> [!TIP] 성능 최적화 팁
> 높은 처리량을 위한 아키텍처 권장 사항입니다.

> [!WARNING] 주요 변경 주의
> 하위 호환성 깨짐 또는 잠재적 장애 위험 경고입니다.
```
*(지원 유형: `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`)*

#### 2.5.6 Mermaid 다이어그램 & LaTeX 수식 (KaTeX)
* **Mermaid 다이어그램**: 선언적 텍스트 기반 순서도 및 시퀀스 다이어그램 자동 렌더링:
  ````markdown
  ```mermaid
  graph LR
      A[마크다운 소스] --> B[Goslide 엔진]
      B --> C[HTML]
      B --> D[PDF]
      B --> E[PPTX]
  ```
  ````
* **LaTeX 수식**: 인라인 `$E=mc^2$` 및 수식 블록 `$$\sum_{i=1}^n x_i$$`
* **작업 체크리스트**: `- [x] 완료 항목`, `- [ ] 예정 항목`

````markdown
## 시퀀스 모델 패러다임 비교

### 기존 구조 (RNN / LSTM)
- **순차 처리 제약**: 이전 은닉 상태 의존으로 병렬화 불가
- **장기 의존성 소실**: 문맥이 길어지면 앞단 정보 유실
- **학습 복잡도**: $O(N)$ 시간 복잡도 누적으로 대규모 학습 한계

<!-- split -->

### 트랜스포머 (Transformer Decoder)
- **완전 병렬화**: GPU 텐서 코어 기반 동시 연산 지원
- **Self-Attention**: 거리와 무관한 $O(1)$ 직접 상관도 계산
- **스케일링 법칙**: 연산량 투입에 비례해 모델 능력 폭발

## Go 스트리밍 프록시 핵심 구현

- **초저지연 스트리밍**: 표준 `http.Flusher`를 활용한 즉각적인 토큰 전달
<!-- pause -->
- **안전한 컨텍스트 취소**: 클라이언트 연결 종료 시 서버 고루틴 즉각 해제

```go {3-5}
func StreamHandler(w http.ResponseWriter, r *http.Request) {
    flusher, _ := w.(http.Flusher)
    for token := range stream.Tokens() {
        fmt.Fprintf(w, "data: %s\n\n", token)
        flusher.Flush()
    }
}
```

<!-- note:
- 3~5번 라인의 토큰 플러시 루프를 설명합니다.
- 코드 라인 포커스와 단계적 빌드가 청중의 시선을 유도하는 효과를 보여줍니다.
-->
````
